# 2E — Schedule / 学校アカウント対応版

スマートフォン向けの曜日別時間割SPA・PWA。`seiko.ac.jp` のGoogle Workspaceアカウントだけが初回に時間割データを取得できます。

## 構成

- **GitHub Pages**：公開してよい画面・時刻計算・ログイン画面だけを `dist/` として配信。
- **Cloudflare Workers**：Google IDトークンを検証し、認証成功時だけ時間割データを返す。
- **端末内**：取得済みの時間割をlocalStorageに保存。Google IDトークンは保存しない。

Googleの署名（RS256）、発行者、対象クライアントID、有効期限、発行時刻、検証済みメール、`hd === seiko.ac.jp` とメールの正確なドメインを検証します。ドメインの似た文字列やサブドメインは許可しません。JWT検証にはjoseを使用しています。

## 最初に読むもの

`SETUP_AUTH.md` の手順で、Google OAuthクライアントとCloudflare Workersを設定してください。

**設定前のまま公開しても、ログインはできません。** `src/config.js` のクライアントID・API URLと、`worker/wrangler.jsonc` のクライアントIDが未入力です。認証を省略するフォールバックはありません。

**リポジトリは非公開に戻し、PagesのSourceはGitHub Actionsに設定してください。** 授業データは `worker/src/timetable.js` とテスト用ソースにあります。Pagesでリポジトリのルートを直接配信すると、この分離が成立しません。公開対象はビルド済みの `dist/` だけです。

## ローカルで更新する

以前のZIPの `schedule` フォルダに、新しいZIP内の `schedule` の中身を上書きしてください。`.github` も含めて上書きします。既存の `.git` はそのまま残せます。このZIPに `.git` と `node_modules` は含まれません。

Node.js 22以上で、`package.json` のあるフォルダから実行します。認証版ではサーバーとテスト用に依存パッケージが増えたため、最初に `npm ci` が必要です。

```powershell
npm ci
npm run check
npm test
npm run build
```

`npm run build` はフロントエンドだけを `dist/` に出力します。Workerやテストのフォルダは含みません。学校の科目・担当情報が紛れ込んだ場合は、ビルドチェックで失敗させます。

## 主な動作

- 月〜土の曜日別ページと直接リンク。曜日変更で再読み込みしない。
- 日本時間で現在・次の授業、休み時間、昼休み、授業終了を表示。
- 平日6限、土曜4限。土曜午後と日曜は月曜1限を案内。
- スリープ復帰、アプリ再表示、BFCache復元、フォーカス、再接続で現在時刻から再計算。
- 手動で選択した曜日を勝手に移動しない。「今日へ」で日付の自動追従に戻れる。
- ライト・ダーク・端末連動。授業時刻を端末ごとに変更できる。
- 一度認証して保存した後は、Googleのセッションが切れていてもオフラインで閲覧可能。
- 設定画面の「Googleで再認証して時間割を更新」で新しいデータを取得。
- 設定画面のログアウトは、このブラウザの保存済み時間割を削除する。

## 保存・権限の範囲

初回ログインは端末・ブラウザ・サイトのオリジンごとに必要です。端末への保存に失敗した場合は、その旨を通知し、そのセッション中だけ利用できます。保存データは暗号化しません。端末を使える人は保存済み時間割を閲覧できます。

学校アカウントを無効化しても、すでに保存されたデータを遠隔から回収しません。オフライン利用を認める仕様です。サイトデータ削除・ブラウザによる保存データの消去・ログアウト後は、オンラインでの再ログインが必要です。

Pages上のログイン画面や画面の構造自体は公開されます。保護するのは授業データです。静的ページ全体の非公開化を実現する構成ではありません。

「現／古」「英Ⅰ／Ⅱ」などは原文を維持。祝日・臨時休校・振替授業・短縮授業は自動判定しません。時間判定は端末の時計に従います。

## 検証と公開

`TESTING.md` に実施済みの自動テストと実機の未確認項目を記載しています。Googleの実アカウントでのログインと実際のCloudflareへのデプロイは、利用者側の設定後に確認が必要です。

GitHub Actionsはpush後に `npm ci`・構文チェック・テスト・ビルド・Pages公開を実行します。Cloudflare APIは `npm run deploy:api` で別途デプロイします。
